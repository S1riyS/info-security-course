# План выполнения ЛР №3

Задание и комментарии преподавателя — в [TASK.md](TASK.md).

Где слайд и комментарии расходятся, ориентир — комментарии: без Проводника, размеры 10 / 40 / 100 ГБ (или 10 / 30 / 40 ГБ), дополнительное задание обязательно.

## Что должно оказаться в отчёте

- Список параметров процесса из **Вид → Выбрать столбцы** и кратко, что показывает каждый (по справке `F1`).
- Параметры компьютера: модель и частота CPU, объём RAM, диск (модель, HDD или SSD, тома, с которого и на который шло копирование).
- Таблица замеров: размер файла, приоритет, режим `Use system copy routine`, время (и скорость, если FAR её показывает). В таблицу — второй и следующие замеры, не первый.
- Снимки экрана в тех местах, где ниже стоит пометка `📸`.

## Шаги

### 0. Подготовка

1. Выбрать размеры по свободному месту.
   На одном томе нужно место под исходный файл и под копию: для 100 ГБ это около 200 ГБ свободно, для 40 ГБ — около 80 ГБ. Файлы трёх размеров одновременно не хранить: отмерили один размер — удалили его и копию, перешли к следующему.
   Если 100 ГБ не влезает или копирование займёт слишком долго — набор 10, 30 и 40 ГБ.
2. Посмотреть параметры машины, их потом надо вписать в отчёт: **Диспетчер задач → Производительность**, либо `Win+R` → `msinfo32`.
   Записать CPU, объём RAM, модель диска и тип (HDD/SSD), буквы томов источника и приёмника.
   📸 take screenshot — вкладка «Производительность» (ЦП, память, диск), пока окно открыто.
3. Поставить FAR (Total Commander — запасной вариант, если FAR нет). Проводник для копирования не использовать: у него общий процесс с оболочкой, смена приоритета задевает рабочий стол.
4. Завести каталог под прогон, например `D:\lab3\`. Источник и копия — в разных каталогах (`D:\lab3\src`, `D:\lab3\dst`).

### 1. Столбцы диспетчера задач

1. Открыть диспетчер задач: `Ctrl+Alt+Del` → «Диспетчер задач», либо `Win+R` → `taskmgr.exe`.
   📸 take screenshot — открытый диспетчер задач.
2. В Windows 10 пункт **Вид → Выбрать столбцы** находится на вкладке **Подробности**. Перейти туда.
3. Открыть **Вид → Выбрать столбцы**. Список длинный, он прокручивается — снять его целиком, прокрутив диалог.
   📸 take screenshot — диалог «Выбрать столбцы», пока он открыт (несколько кадров, если не влезает).
4. Для каждого параметра выписать название и что он показывает. Справка: фокус в диспетчере задач и `F1`, либо описание в самом диалоге. В отчёт — полный список, не только столбцы, включённые по умолчанию.
5. Имеет смысл включить столбцы, которые понадобятся дальше: **Имя образа**, **ИД процесса**, **Базовый приоритет**, **ЦП**, **Память**.

### 2. Файлы для копирования

Файл должен быть обычным, несжатым и не разреженным (не sparse). `fsutil file createnew` создаёт разреженный файл: чтение почти не трогает диск, копирование получается не тем, что измеряет лабораторная, и приоритет почти не виден.

1. Оценить, сколько займёт прогон. На каждый размер — 2 режима копирования × 3 приоритета × минимум 2 прогона (прогрев и зачётный). Это 12 копирований одного файла. На HDD набор с файлом 100 ГБ легко занимает несколько часов; на SSD заметно быстрее. Поэтому размер выбирается до генерации файлов, а не после.
2. Создать несжатый файл нужного размера одним из способов:
   - скопировать уже существующий большой файл (образ диска, архив, видео), если он не сжат «на лету» и не является sparse;
   - записать файл данными, например так (размер в байтах, каталог свой):

```powershell
$path = "D:\lab3\src\file10.bin"
$size = 10GB
$buf = New-Object byte[] (8MB)
$rng = [System.Random]::new()
$fs = [System.IO.File]::Create($path)
try {
    $left = $size
    while ($left -gt 0) {
        $n = [Math]::Min($buf.Length, $left)
        $rng.NextBytes($buf)
        $fs.Write($buf, 0, $n)
        $left -= $n
    }
}
finally { $fs.Dispose() }
```

   Для 30 / 40 / 100 ГБ поменять `$size` и имя. Генерация случайных данных сама по себе долгая; если есть готовый большой файл подходящего размера, он удобнее.
3. Проверить в свойствах файла, что размер и «размер на диске» близки. Если «размер на диске» около нуля — файл разреженный, для замера он не подходит.
   📸 take screenshot — свойства файла: размер и размер на диске.

### 3. Приоритет и замеры

Приоритеты из задания, как они названы в диспетчере задач:

| В задании | В диспетчере задач |
| --- | --- |
| низкий | Низкий |
| выше среднего | Выше среднего |
| реального времени | Реального времени |

Приоритет реального времени может на время копирования подвесить интерфейс: FAR перестанет реагировать, пока идёт копия. `Ctrl+Alt+Del` при этом обычно открывается. Ставить его только на процесс файлового менеджера и только на время замера, сразу после замера вернуть **Обычный**. Если пункт недоступен — открыть диспетчер задач от имени администратора.

Порядок приоритетов в прогоне: **Низкий → Выше среднего → Реального времени**.

Для одной ячейки таблицы (один размер, один приоритет, один режим копирования):

1. Запустить FAR. В диспетчере задач на вкладке **Подробности** найти `far.exe` (у Total Commander — `TOTALCMD.EXE` или `TOTALCMD64.EXE`).
   📸 take screenshot — процесс файлового менеджера в списке, пока диспетчер задач открыт.
2. Правый щелчок по процессу → **Задать приоритет** → нужный уровень.
   📸 take screenshot — меню приоритета с выбранным пунктом, пока меню открыто.
3. Убедиться по столбцу **Базовый приоритет**, что значение сменилось.
4. В FAR скопировать файл из `src` в `dst` (клавиша копирования — `F5`). Дождаться конца. Время и скорость взять из окна копирования FAR.
   Первый прогон — прогрев кэша, в отчёт его не ставить (можно записать в черновик).
5. Удалить файл из `dst`.
6. Повторить копирование с тем же приоритетом. Это зачётный замер — его в таблицу. Если есть время, сделать третий: в отчёт идут второй и последующие. Если второй и третий сильно разошлись, сделать ещё один, чтобы отделить кэш от случайного разброса.
   📸 take screenshot — окно копирования FAR с размером, временем и скоростью; рядом или следом кадр диспетчера задач, где видно приоритет `far.exe`. Снимок нужен по одному разу на каждый приоритет, не на каждый повтор.
7. Снова удалить копию из `dst`. Вернуть приоритет **Обычный**, если следующим шагом не нужен другой.

Так пройти три приоритета для текущего размера. Затем следующий размер: новый файл, те же три приоритета, старый файл удалить.

Куда писать числа (режим копирования — в следующем шаге; для базовой части можно сначала заполнить одну из двух половин):

| Режим `Use system copy routine` | Размер | Приоритет | Замер | Время | Скорость |
| --- | --- | --- | --- | --- | --- |
| выкл / вкл | 10 / 40 / 100 ГБ | Низкий / Выше среднего / Реального времени | 2 (и 3, если был) | | |

Первый замер в эту таблицу не входит.

### 4. Доп. задание (обязательно)

Та же сетка замеров ещё раз, во втором режиме копирования FAR. Имеет смысл для каждого размера сразу снять оба режима, пока файл ещё не удалён: сначала все приоритеты с выключенной опцией, потом все приоритеты с включённой, и только потом удалять файл.

1. В FAR открыть **Options → System settings** (в русской сборке: **Параметры → Системные параметры**).
2. Найти **Use system copy routine** (в русской сборке: «Использовать системную функцию копирования»).
   📸 take screenshot — системные параметры с выключенным флажком, пока диалог открыт.
3. Прогнать три приоритета, как в шаге 3. В таблицу писать режим «выкл».
4. Включить флажок, закрыть диалог.
   📸 take screenshot — тот же диалог с включённым флажком, пока он открыт.
5. Прогнать те же три приоритета ещё раз. В таблицу писать режим «вкл».
6. Удалить исходный файл и копию, перейти к следующему размеру.

Оба режима обязательны для каждого размера и каждого приоритета. Иначе доп. задание закрыто только наполовину.

2. Удалить тестовые файлы из `src` и `dst`.
